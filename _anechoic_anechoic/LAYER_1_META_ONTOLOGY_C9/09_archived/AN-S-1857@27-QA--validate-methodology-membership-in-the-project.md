## Summary

Validate Methodology membership in the Project

## Claim

the Methodology Scope Units belong **to** the anechoic Project Scope Unit tree **and** remain governed by its active Project-owned Tier 0 Atoms.

## Test case

resolve the current Project Scope Unit tree from authoritative ownership declarations **and** locate FRAMEWORK_METHODOLOGY, METHODOLOGY_SOURCES, **and** its source Scope Units. verify their ancestry **to** anechoic **and** their authority Directory Carriers. include their active Atoms **in** Project Scope Contract-first alignment checks. **then** place a Methodology Scope Unit outside that tree, author or persist a Structural Level property for a current anechoic Scope Unit, register a Bootstrap Scope Unit as part of the current anechoic structure, exempt Methodology from a Project-owned Tier 0 Atom, **or** represent an Atom's different Claim Target Scope Unit as an additional Scope Unit edge.

## Acceptance criteria

**every** current Methodology Scope Unit has a parent chain **to** anechoic. any displayed ancestry depth or path is derived from that parent chain only and does not establish another authored source of ancestry. its source Carrier placement does **not** exempt it from Project authority. the ordinary Project Scope Contract-first checks include its active Atoms. **all** invalid fixtures fail. the Core Meta-Model's optional support for Bootstrap Scope Units does **not** activate them for anechoic. the external Project Goal's Tier **`-1`** remains valid and does not create or imply a Scope Unit depth. archived Bootstrap records remain historical evidence **without** becoming current Scope Units.

## Failure disposition

record a Concern identifying the incorrect owner, authored or persisted Structural Level property, Carrier binding, Project Scope Contract exemption, **or** invented Scope Unit edge.
